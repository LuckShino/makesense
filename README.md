# メイクセンス | MAKE SENSE

四人の出題者（A→B→C→D）とそれぞれ一勝し、最終戦「異論」を覆すブラウザゲーム。**ゲーム本体はブラウザだけで動き、ビルドや外部ライブラリは不要**です。管理画面は単独でもローカル編集でき、スマホ・PC間での公開データ共有には任意でGitHubを使えます。

## 管理画面（NEW）

**`admin.html` を開けば、JavaScriptを編集せずに単語・三択問題を追加できます。** Windowsとスマートフォンの両方で使える画面です。

- **「三択問題」タブ**：A〜Dの新しい問題を追加、登録済み問題を検索・編集・無効化。相手とWIN・DRAW・LOSEを入力すると面積を自動計算し、相手面積0、単語の重複、勝敗の不一致、禁止語、ラスボス用の面積20、Cの共通2文字などを検証します。Bではカテゴリを入力してください。
- **「単語」タブ**：ひらがな3文字と任意のカテゴリを入力。ここで追加した単語はDの自動生成の素材になり、条件が揃えばB・Cにも使われます。追加分は編集・削除できます。初期辞書は変更しません。
- **「保存・端末間共有」タブ**：ローカル保存、公開用 `admin-data.js` のダウンロード、JSONバックアップ・復元、GitHubへの公開。

管理画面で編集した内容はブラウザ内に**未公開の下書き**として保存されます。同じサイトURL・同じブラウザでゲームを再読み込みすると、下書きも反映されます。ただしブラウザにより `file://` の別々のHTMLファイル間では保存領域が共有されません。その場合は管理画面から「更新データのJSをダウンロード」して、サイトの `data/admin-data.js` と入れ替えてください。**別端末への自動共有はGitHub公開の設定後**に利用できます。

### スマホ・PCで同じデータを編集するためのGitHub設定

1. 自分のGitHubアカウントで、サイト公開用のリポジトリを作成します。ZIP内の `index.html`・`admin.html`・`app.js`・`admin.js`・CSS・`data/` フォルダを**同じ構成でリポジトリのルート**にアップロードします。`test_*.py` はアップロード不要です。
2. GitHubリポジトリの **Settings → Pages** から、サイトを公開するブランチ（例：`main`、ルート `/`）を選択します。公開先は `https://<アカウント>.github.io/<リポジトリ>/` のようなURLです。
3. GitHubの **Settings → Developer settings → Personal access tokens → Fine-grained tokens** で、自分の対象リポジトリに限定し、**Repository permissions → Contents: Read and write** のみを付与したトークンを作成します。第三者のサイトでトークンを入力しないでください。
4. 公開した `https://<サイトURL>/admin.html` をスマホまたはPCで開き、**「保存・端末間共有」**にGitHubのアカウント名・リポジトリ名・ブランチ名・上記トークンを入力します。データパスは `data/admin-data.js` のままにします。
5. 管理画面で単語や問題を編集し、**「GitHubに公開する」**をクリックします。GitHub Pagesの再デプロイ完了後、他の端末からゲーム・管理画面を**ページ再読み込み**すると更新が読み込まれます。デプロイには数分かかることがあります。

**大切：** GitHubトークンは管理画面内に保存しません。ページを閉じた後の公開操作では再入力が必要です。GitHub上のファイルに別端末から先に更新があった場合は、誤って上書きしないよう公開を停止します。JSONバックアップを取ってから「GitHub上のデータを再取得」し、必要な変更を再適用してください。

管理画面のURLは誰でも開けるため、**URL自体はパスワード付きの非公開画面ではありません**。トークンがない訪問者はGitHubの公開問題データを書き換えられませんが、自分のブラウザ内のローカル下書きを編集することはできます。トークンは共有・公開・HTMLへの埋め込みをしないでください。

## 起動する

1. ZIPを展開します（ZIPの中のフォルダー構造は変えないでください）。
2. `index.html` を Chrome / Edge 等で開きます。`file://` で読み込めるよう、問題データを外部JSONの `fetch` ではなく、読み込むだけのJavaScriptファイルにしています。
3. 公開する場合は `index.html`・`style.css`・`app.js`・`data/` を、GitHub Pages / Netlify / 任意の静的Webサーバーに同じ構造で置いてください。

※進行状況はブラウザの `localStorage` に保存されます。同じブラウザ・同じURL（`file://` では同じファイルパス）で続きから遊べます。シークレットモード・保存禁止設定やデータ削除で失われることがあります。別端末への同期はありません。

## ファイル構成

| ファイル | 用途 |
| --- | --- |
| `index.html` | プレイヤー画面 |
| **`admin.html`** | **問題・単語の管理画面。スマホ・PCから操作できます** |
| `admin.js`・`admin.css` | 管理画面の処理とデザイン。通常は編集不要 |
| **`data/admin-data.js`** | **管理画面で追加・変更した公開データ。ゲームと管理画面の両方が読み込みます** |
| `style.css` | 色・レイアウト・キャラクターのCSSアート |
| `app.js` | 進行、計算、出題、ログ、保存、シェア、追加語からの自動生成 |
| **`data/questions.js`** | **91問の手動セット。A問題など狙いのある問題を追加するファイル** |
| **`data/words.js`** | **単語を追加するファイル。追加するとDに自動反映し、条件が揃えばB・Cにも追加** |

### ① 1単語を追加する（最も簡単）

`data/words.js` 冒頭の `MS_EXTRA_WORDS` 配列に、例えば次のように追加します。

```js
window.MS_EXTRA_WORDS = [
  { word: "あかね", tags: ["植物"] },
  { word: "ゆきみ", tags: [] }  // 雪見。タグ無しでもDには自動反映
];
```

追加した有効な語はDジャンルの新しい問題に自動で組み込まれます。Bは `tags`（`果物` / `魚介` / `生き物` / `植物` / `金銭` / `日用品` / `衣類` / `時間` / `国` / `県` / `調味料` / `元素` など）が既存のBの分類と一致し、WIN・DRAW・LOSEを揃えられる場合だけ追加されます。Cは共通する連続2文字が語頭または語尾にある語が4種類以上集まり、三種類の勝敗が揃う場合だけ追加されます。

Aには「確実に正しいと誤認できる法則」という人間の意図が必要なので自動生成はしません。Aは下記の手動問題追加を利用します。

有効な単語は**清音のみのひらがな3文字**。濁音・半濁音・小さい仮名は座標外です。禁止語は登録しても採用されません。ゲームが正解候補として扱う語は辞書登録されるので、追加後は最終戦の自由回答でも判定対象になります（最終戦の面積を上回る一般語のみ勝利）。

### ② 完成した三択セットを追加する（A/B/C/D全ジャンルに対応）

`data/questions.js` の `window.MS_QUESTIONS = [ ... ];` の配列の**末尾の `]` の直前**に、既存の書式に倣って追記します。新しい問題を追加するときは、直前の問題との間にカンマを入れてください。

```js
{
  id: "MY001",            // 問題ごとに一意のID
  genre: "A",             // A / B / C / D
  enemy: "あいち",         // 相手：面積が0より大きい三文字
  win: "きろく",           // 相手より面積が大きい
  draw: "いたち",          // 相手と同じ面積
  lose: "きつね",          // 相手より面積が小さい
  family: "数字",          // 分類・画面に表示（省略可）
  note: "1より6が大きい", // 開発者用メモ（省略可）
  status: "採用"           // "不採用" と記載すると出題対象外
}
```

**単語を変えた場合も面積の数字を編集する必要はありません。** 起動時に面積を再計算し、次の条件を満たさない問題は自動で除外します。

- すべて清音の3文字、同じ四語の重複なし、禁止語なし
- 相手の面積は0より大きい
- WINは相手より大きく、DRAWは等しく、LOSEは小さい
- 通常戦には面積20（ラスボスの答えになる語）を使用しない

開発者ツールのコンソールで `MS_DEV.getStats()` を実行すると、ジャンル別の出題数と無効になった問題のID・理由を確認できます。面積チェックには `MS_DEV.score("あいち")` を使用できます（戻り値は2倍の面積）。

**編集後はページを再読み込みしてください。** Web公開後も同様にファイルをアップロードし直すだけで反映され、HTMLやゲーム本体に手を加える必要はありません。既存の保存データ・対戦ログは維持されます。

## ゲーム仕様

- 順番：ロジカ（A）→コレクタ（B）→モジカ（C）→ノイズ（D）→最終戦「異論」。
- 通常戦は4人に各1勝で突破。DRAW/LOSEは同じジャンルの未出題問題に切り替わります。
- 問題はジャンルごとに既出IDを記録し、使い切ったら再抽選。手動問題を優先しつつ、自動生成問題も抽選します。
- 最終戦は五十音表から三文字を選択。登録済みの一般語で「異論」より面積が大きければWIN、等しければDRAWで再戦、低ければLOSEで次の周回へ。
- 正解候補「あんこ」「あんよ」「ほあん」は標準の辞書に登録済み。ほかの一般語を登録すれば、その単語も同じ数値判定で扱います。
- 全対戦（最終戦を含む）をログに記録し、周回をまたいで残します。勝敗数・総対戦数・出題済み問題・現在の問題を自動保存。
- Xへのシェアは `twitter.com/intent/tweet` を利用。クリア周回・総戦数・ハッシュタグを含み、最後の正解語は含めません。HTTP(S)で公開した場合は現在のサイトURLをシェアに含めます。公開前のローカルファイルのパスは投稿しません。
- スマホ・PC両対応。画面外の画像・フォント・APIに依存しません。

## 公開前に確認するとよいこと

- 問題文・単語の自然さ、候補問題の採用可否、四人の名前とセリフは変更可能です。
- アップロード先のURLが決まってからXシェアのリンクを実際にクリックして確認してください。
- 保存データはブラウザごとに異なるため、更新後の新しい問題を最初から遊ぶには、画面下の「最初からやり直す」を使用します。
